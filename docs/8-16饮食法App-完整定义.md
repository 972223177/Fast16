# 第一部分 · 数据表完整 DDL

> 说明：Room 通过 `@Entity` 生成 SQL，以下为**等价 DDL**（作为评审与迁移基准）；枚举列统一存 `Int`（`TypeConverter` 映射），字符串列加长度约束。

## 1.0 枚举定义（Int 存储）

| 枚举 | 值 | 说明 |
|------|----|------|
| `MealType` | `BREAKFAST=0 / LUNCH=1 / DINNER=2` | 餐次类型 |
| `PlanStatus` | `ACTIVE=0 / ARCHIVED=1` | 计划状态 |
| `MealStatus` | `SCHEDULED=0 / PREPARING=1 / EATING=2 / COMPLETED=3` | 餐次状态机 |
| `ReminderMode` | `NONE=0 / NOTIFY=1 / VIBRATE=2 / SOUND=3 / ALARM=4` | 提醒模式（V1 = NOTIFY + 固定轻短震动；可配置 VIBRATE / SOUND / ALARM 为 M3 扩展） |

## 1.1 `meal_plans`（就餐计划）

```sql
CREATE TABLE meal_plans (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    date              TEXT    NOT NULL,   -- ISO 'yyyy-MM-dd'
    window_start_epoch INTEGER NOT NULL,  -- 早餐时间（毫秒）
    window_end_epoch   INTEGER NOT NULL,  -- windowStart + windowHours
    status            INTEGER NOT NULL DEFAULT 0,  -- PlanStatus
    created_at_epoch  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_plan_date ON meal_plans(date);   -- 一天最多一个计划
```

## 1.2 `meals`（餐次）

```sql
CREATE TABLE meals (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    plan_id         INTEGER NOT NULL,
    type            INTEGER NOT NULL,               -- MealType
    meal_time_epoch INTEGER NOT NULL,               -- 「开始吃」时刻
    prep_minutes    INTEGER NOT NULL DEFAULT 0,     -- 餐前准备时长；0 = 无 PREP 阶段
    status          INTEGER NOT NULL DEFAULT 0,     -- MealStatus
    reminder_mode   INTEGER NOT NULL DEFAULT 1,     -- ReminderMode（继承全局偏好）
    FOREIGN KEY(plan_id) REFERENCES meal_plans(id) ON DELETE CASCADE
);
CREATE INDEX idx_meals_plan ON meals(plan_id);
```

> `prep_time` 不落库，由 `meal_time_epoch − prep_minutes * 60_000` 派生（单一事实源）。

## 1.3 `check_ins`（打卡记录）

```sql
CREATE TABLE check_ins (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    date              TEXT    NOT NULL,   -- ISO 'yyyy-MM-dd'
    meal_type         INTEGER NOT NULL,   -- MealType
    checked_at_epoch  INTEGER NOT NULL    -- 打卡时间戳
);
CREATE UNIQUE INDEX uq_checkin_date_meal ON check_ins(date, meal_type);  -- 幂等
```

> `(date, meal_type)` 复合唯一 → 重复打卡用 `INSERT ... ON CONFLICT DO UPDATE`（Room `@Upsert`）覆盖 `checked_at_epoch`。

## 1.4 DAO 接口（最小契约）

| DAO | 方法 |
|-----|------|
| `MealPlanDao` | `watchByDate(date)` / `upsert(plan)` / `deleteById(id)` / `watchToday()` |
| `MealDao` | `watchByPlan(planId)` / `upsertAll(meals)` / `updateStatus(id, status)` / `watchTodayMeals()` |
| `CheckInDao` | `watchMonth(yearMonth)` / `checkIn(date, mealType, at)`(UPSERT) / `uncheckIn(date, mealType)` / `completedDaysInRange(from, to)` |

## 1.5 DataStore 偏好 Schema（键值，非表）

| Key | 类型 | 默认 |
|-----|------|------|
| `window_hours` | Int | `8` |
| `min_meal_gap_minutes` | Int | `180` |
| `dinner_buffer_minutes` | Int | `30` |
| `default_prep_lunch_minutes` | Int | `30` |
| `default_prep_dinner_minutes` | Int | `45` |
| `default_prep_breakfast_minutes` | Int | `0` |
| `default_reminder_mode` | String | `NOTIFY` |
| `widget_show_fasting` | Bool | `true` |
| `onboarding_seen` | Bool | `false` |

## 1.6 Room 工程约定

- Room **3.0.x** + KSP；`schemaVersion` 从 `1` 起，导出 schema JSON 做迁移测试。
- 迁移纪律：改表 → 升 `schemaVersion` → 写迁移（必要时 `CREATE TABLE new` + 回填 + 显式 `CREATE INDEX` + `DROP old`）；新增唯一索引必须处理脏数据去重后再建。
- 枚举统一 `Int` 列 + `TypeConverter`；字符串列 `@ColumnInfo` 加长度约束。
- **SSOT 原则**：UI 只订阅 DAO 的 `Flow`，一切写入走 `upsert`，禁止内存副本手动同步。

# 第二部分 · 推理与统计算法伪码

> 全部为**纯函数**（无 Android 依赖），放 `domain/schedule/` 与 `domain/stats/`，单测覆盖。
> **MVI 定位**：这些纯函数即 feature 的 **Reducer / UseCase 逻辑**——时间、打卡等输入由调用方（ViewModel）注入，函数只做 `输入 → 输出` 的确定性转换。

## 2.1 候选生成（CandidateGenerator）

```kotlin
data class Candidate(val label: String, val lunch: Instant, val dinner: Instant)

fun generateCandidates(B: Instant, W: Duration, minGap: Duration, bufferEnd: Duration): List<Candidate> {
    val L = W - bufferEnd - minGap                    // 午/晚排布总弹性
    val winEnd = B + W

    // 方案1 · 均衡
    val lunch1 = B + W / 2
    val dinner1 = minOf(winEnd - bufferEnd, lunch1 + minGap + L / 2)

    // 方案2 · 午餐偏早
    val lunch2 = B + minGap + L * 0.25
    val dinner2 = lunch2 + minGap

    // 方案3 · 晚餐偏晚
    val lunch3 = B + minGap + L * 0.75
    val dinner3 = winEnd - bufferEnd

    return listOf(
        Candidate("均衡",     lunch1, dinner1),
        Candidate("午餐偏早", lunch2, dinner2),
        Candidate("晚餐偏晚", lunch3, dinner3),
    )
}
```

## 2.2 约束校验（Validator）

```kotlin
fun validate(lunch: Instant, dinner: Instant, B: Instant, W: Duration,
             minGap: Duration, bufferEnd: Duration): List<String> {
    val errors = mutableListOf<String>()
    if (lunch < B + minGap)       errors += "午餐需在早餐后至少 ${minGap.toMinutes()} 分钟"
    if (dinner < lunch + minGap)  errors += "晚餐需在午餐后至少 ${minGap.toMinutes()} 分钟"
    if (dinner > B + W - bufferEnd) errors += "晚餐不能晚于窗口结束前 ${bufferEnd.toMinutes()} 分钟"
    return errors
}
```

## 2.3 餐次状态推进（MealStateMachine）

> `status` 落库，但可由「时间 + 打卡」重算；前台时做一次 reconcile，避免闹钟漏触发导致状态滞留。

```kotlin
fun advance(meal: Meal, now: Instant, hasCheckIn: Boolean): MealStatus {
    val prep = meal.mealTime - meal.prepMinutes.minutes
    return when {
        hasCheckIn -> COMPLETED
        meal.prepMinutes > 0 && now >= prep && now < meal.mealTime -> PREPARING
        now >= meal.mealTime -> EATING
        else -> SCHEDULED
    }
}
```

## 2.4 角色状态派生（CharacterState）

```kotlin
fun deriveCharacterState(now: Instant, plan: MealPlan?, meals: List<Meal>): CharacterState {
    if (plan == null || meals.isEmpty()) return IDLE

    meals.firstOrNull { m ->
        m.prepMinutes > 0 && now >= (m.mealTime - m.prepMinutes.minutes) && now < m.mealTime
    }?.let { return PREP }

    meals.lastOrNull { m -> now >= m.mealTime && m.status != COMPLETED }?.let { return EATING }

    if (meals.all { it.status == COMPLETED }) return REST
    return FASTING          // 窗口外 / 两餐之间
}
```

> 优先级天然满足：`PREP`（进行中）→ `EATING`（进行中）→ `REST`（全完成）→ `FASTING`（兜底）。

## 2.5 断食剩余时间（NextAction）

```kotlin
fun nextAction(now: Instant, meals: List<Meal>): Instant? =
    meals.map { m ->
        if (m.prepMinutes > 0) m.mealTime - m.prepMinutes.minutes else m.mealTime
    }.filter { it > now }.minOrNull()

fun fastingRemaining(now: Instant, meals: List<Meal>): Duration? =
    nextAction(now, meals)?.let { it - now }
```

## 2.6 连续打卡（Streak）

```kotlin
fun computeStreak(completedDays: Set<LocalDate>, today: LocalDate): Int {
    var cursor = if (completedDays.contains(today)) today else today.minusDays(1)
    var streak = 0
    while (completedDays.contains(cursor)) { streak++; cursor = cursor.minusDays(1) }
    return streak
}
```

> `completedDays` = 当日三餐均存在的日期集合，由 `CheckInDao.completedDaysInRange` 聚合。

## 2.7 完成率（月 / 周）

```kotlin
fun monthCompletion(completedDays: Set<LocalDate>, ym: YearMonth): Float {
    val total = ym.lengthOfMonth()
    val done  = completedDays.count { it.year == ym.year && it.month == ym.month }
    return if (total == 0) 0f else done.toFloat() / total
}

fun weekCompletion(completedDays: Set<LocalDate>, week: List<LocalDate>): Float =
    week.count { it in completedDays }.toFloat() / week.size
```

# 第三部分 · 页面组件清单与像素动效分镜

| `PixelToast` | 轻提示 | 黑底白字 + 边框，弹出式 |

## 3.1 Onboarding（首次引导）

**组件清单**：`PixelDialog` + `PixelBubble`（小健举牌）+ `PixelButton`(知道了) + 进食/断食 `PixelProgressBar` 示意。

**动效分镜**：

| 时序 | 动效 |
|------|------|
| 进入 | 黑屏闪白一帧（60ms）→ 弹窗 scale 0→1（阶跃 3 步） |
| 角色出场 | 小健举牌帧（2 帧循环） |
| 进度条示意 | 8h/16h 两段色块逐格点亮（一次性，约 400ms） |
| 关闭 | 像素淡出（alpha 1→0 阶跃）→ 回首页 |

## 3.2 Home（今日首页）

**组件清单**：断食剩余 `PixelNumber`、`PixelProgressBar`、三餐时间轴（`PixelTimeAxis`）、角色 `PixelSprite` + `PixelBubble`、`PixelButton`(新建/打卡)。

**动效分镜**：

| 状态 | 角色动效 | 时间轴反馈 |
|------|----------|-----------|
| IDLE | 呼吸 + 眨眼（2 帧） | 全灰 |
| FASTING | 小跑/举铁/冥想（随机 3 选 1） | 当前餐「待机」黄框 |
| PREP | 切菜/颠锅（2 帧，加速） | 当前餐高亮 + 黄闪 |
| EATING | 吃饭/咀嚼（2 帧） | 当前餐绿框 |
| REST | 拉伸/比赞（2 帧）+ 气泡「完成」 | 全绿 |
| 打卡成功 | 图标「跳一格」+ 气泡弹出 | 该餐点亮绿 |

## 3.3 Create（新建计划）

**组件清单**：时间选择器（`PixelTimePicker`，步进 ±5min）、候选卡片（`PixelCard` ×3，选中黄描边）、微调区（午/晚时间 + 备餐时长滑杆 `PixelSlider`）、`PixelButton`(生成)。
