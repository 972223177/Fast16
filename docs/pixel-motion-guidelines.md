# 像素风交互动效规范（Pixel Motion）

> 依据像素动画社区规范（12 动画原则的像素适配、帧率与帧时长惯例，2026 版检索）整理，适配本项目「深色像素风 App UI」场景；不直接照搬 Material 3 motion。交互类业务动效**优先配上**——动效不是可选装饰，是像素风手感的一半。写作/Review 动效时必读。

## 0. 总原则：少帧、阶跃、短促、有分量

| 原则 | 要求 |
|------|------|
| **阶跃优先** | 动画按离散帧阶跃呈现，禁用连续平滑插值（tween/spring）带来的「果冻感」；阶梯感是像素美学的一部分，不是缺陷 |
| **帧数克制** | 4 帧精心设计的动画优于 8 帧平庸动画；删掉删了也感知不到的帧 |
| **短促** | 交互反馈整体落在 **60–200ms** 级（空态等待循环等氛围动效除外）；「冲击/成功」帧刻意拖长，过渡帧快速带过；M3 时长仅作上限参考，像素动画普遍更短促 |
| **整数像素** | 所有位移/尺寸变化对齐像素网格，禁亚像素偏移；渲染保持 `FilterQuality.none` + 整数倍缩放 |
| **节奏变化** | 变化每帧时长表达重量：冲击帧 120–200ms、过渡帧 60–80ms；全程匀速 = 机械感（最大忌） |
| **反馈对称** | 有进场必有退场；有慢入必有慢出 + recovery settle |
| **可读性 > 真实性** | 动效要一眼能读懂发生了什么（眯眼测试） |

## 1. 交互类业务动效清单（必须配置）

| 场景 | 动效 | 规格 |
|------|------|------|
| 按压反馈 | 按下下沉 1px（位移，非缩放）/ 高亮闪帧 | 1–2 帧，~80ms，抬起即回 |
| 打卡 / 勾选成功 | 勾选图形阶跃画出 + 高亮闪帧 | 2–3 帧，~120–200ms，成功帧拖长 |
| 状态切换（tab/分段） | 指示块整数像素滑动或直接跳帧 | 2–3 帧，~100–150ms |
| 计数 / 进度变化 | 数字跳变 + 1 帧高亮 | 1–2 帧 |
| 页面/弹窗进出 | 阶跃滑入滑出或跳切 | 进 3–4 帧（~150ms），出 1–2 帧（~80ms，出场比进场快） |
| 空态/占位 | 待机循环（呼吸/眨眼式） | 2–4 帧，每帧 300–500ms |
| 气泡/浮层弹出 | 从锚点阶跃展开（整数像素尺寸跳变，不做平滑缩放）+ 尾角滞后摆动 1–2 帧 | 出现 2–3 帧（~100–150ms），消失 1–2 帧（~80ms） |
| 文字显示 | 打字机逐字阶跃（typewriter）或整段跳入 + 光标闪烁循环 | 逐字 1 帧 30–60ms/字符；光标 2 帧 ~400ms 循环 |
| 破坏性操作确认 | 抖动 + 红色闪帧 | 2 帧，~100ms |

## 2. 像素化表达手法（UI 场景）

- **UI 元素禁用 squash/stretch**（挤压拉伸）——那会让界面「像果冻」；UI 反馈用**位移、闪烁、抖动、变色**表达。
- **高亮闪帧**（hit-flash）：状态变化瞬间亮 1 帧（颜色反相/提亮），再落回正常色——像素 UI 最有效的成功反馈。
- **预备帧（anticipation）**：大幅变化前加 1 帧反向铺垫（如对话框弹出前整体反向位移/下沉 1 帧），1 帧即可消「漂浮感」。
- **次级动画**：主体停止后尾巴再动 1–2 帧（如飘动的角标、延迟落定的徽标）。
- **像素震动**：错误/警告反馈可用 1–2 帧的 1px 抖动，勿滥用。
- **文字动效**：像素文字只支持整数倍缩放与整字显隐——打字机逐字阶跃（信息流/引导语最出像素味的手法）；**禁用逐字符 alpha 渐显/位移动画**（亚像素平滑，破坏像素感）；光标闪烁固定 2 帧。
- **气泡动效**：弹出尺寸必须落在像素网格上逐帧跳变（如 0 → 半尺寸 → 全尺寸三帧），不做连续 scale；气泡尾角（箭头）可加 1–2 帧独立滞后摆动（次级动画）。
- **像素溅射（splash，可选增强）**：仅用于高价值/庆祝类操作（打卡成功、里程碑达成），普通按钮**不加**（避免视觉噪音稀释关键反馈）。规格：按压点迸出 **6–12 个 1–2px 粒子**，2–4 帧阶跃扩散 + 1 帧消散，与高亮闪帧同帧触发；禁平滑渐隐（消散即整帧消失）。实现必须走**单个 Canvas**（`drawBehind` 内绘制全部粒子），严禁每粒子一个 Composable（每帧重组灾难，见 compose-performance.md）。
- 禁用模糊、渐隐过渡、抗锯齿缩放——与 `FilterQuality.none`、整数网格铁律冲突。

## 3. Compose 实现约束

- **阶跃实现**：优先离散帧切换（状态机 + `withFrameMillis` 分步），或对动画值做像素取整 snap；避免 `spring()`、`FastOutSlowIn` 等连续曲线的平滑观感。
- **时长用帧表达**：以「帧数 × 每帧毫秒」思考（如 4 帧 × 120ms ≈ 8fps 的阶跃观感），不是连续 duration。
- 动效时长/帧时序定义进 `PixelTokens`（与 AGENTS.md §6 像素风规范一致），业务组件不得裸写毫秒。
- 动画期间逐帧保证**体积/轮廓一致**：同元素跨帧像素尺寸不变（除非有意形变），防止「逐帧漂移」。
- 性能约束见 [`docs/compose-performance.md`](docs/compose-performance.md)：动画状态用 lambda 版修饰符（`offset {}` / `drawBehind {}`）读取，避免每帧重组。
